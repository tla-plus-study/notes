\section*{Brief Description of the Topics}

\subsection*{Lecture 1}

What is TLA+, for what can it be used and how it's helpful.

\begin{itemize}
  \item A tool for specification, finding and correcting design errors.
  \item Well suited for parallel and distributed prgraming.
  \item TLA+ sits at the design level/above the code level.
  \item It abstract less-critical/lower level parts of sytems.
  \item The properties TLA+ can check are conditions on individual executions
  (i.e 99\% of executions are correct is not a property testable by TLA+)
  \item Execution of a system is represented as a sequence of discrete steps
  \item TLA+ represents systems as state machines.
\end{itemize}


\subsection*{Lecture 2}

State Machines and TLA+ notation.

\begin{itemize}
  \item { TLA+ operates on formulas not statements. }
\end{itemize}

Language keywords

\begin{description}
  \item[\texttt{TRUE}] { true }
  \item[\texttt{FALSE}] { false }
  \item[\texttt{/\textbackslash}] { logical and }
  \item[\texttt{\textbackslash/}] { logical or }
  \item[\texttt{=}] { equality }
  \item[\texttt{==}] { $\triangleq$  }
  \item[\texttt{'}] { next state i.e $\texttt{pc'} = \texttt{pc} + 1$   }
  \item[\texttt{EXTENDS}] { module import }
  \item[\texttt{VARIABLES}] { variable declarations }
\end{description}
